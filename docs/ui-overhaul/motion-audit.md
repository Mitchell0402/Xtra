# 交互动效审计与改进计划（初稿）

日期：2026-11-18。基于 master `0e334047`（U9 合并后，tag `ui-u9`）。流程：**初稿（本文）** → 审阅 → 修改 → 审阅 → 修改 → Mitchell 批准。批准前不改代码。

目标：每一个界面变化都有动画，同一类变化用同一种动画，数值全部来自 `LagoonMotion`（U1 定的四档时长、两条曲线、两种弹簧）；性能不能比 v0.2 差。旧安卓版本的兼容不作要求（minSdk 29 不变，但新效果可以只在 Android 14+ 上做）。

## 0. 怎么查的

- **代码**：在 `app/src/main/java/.../ui` 里搜 `AnimatedContent`、`AnimatedVisibility`、`animate*AsState`、`Animatable`、`tween`/`spring`、`SharedTransitionLayout`、`BackHandler`/`PredictiveBackHandler`、Navigation 转场、Fragment 事务、Activity 启动，共 183 处，逐处看过；再按“每个会让界面变样的操作”反查有没有动画（没有动画的地方搜不到，只能反查）。
- **录屏**：模拟器 emulator-5554（Pixel 10 Pro XL，API 37，swiftshader 软件渲染，已登录的数据快照），装 U9 qa 包，`screenrecord` 录了 11 段，每段抽出“和上一帧不同”的帧拼成联系表。录屏、联系表和脚本在 `E:/Projects/Lagoon-audit/motion/`（`rec.py` 录制，`sheetonly.py` 按时间段出表）。
- **局限**：软件渲染下模拟器只有约 11–16 帧/秒，300 ms 的转场只能拍到 2–4 帧，所以录屏只用来回答“有没有动画、方向对不对、有没有闪黑/跳动”，不能回答“顺不顺”。顺不顺、掉不掉帧要在手机上量（见第 6 节）。平板形态只看了代码，没录。
- 手机没碰（另一个线程可能在用电脑；按要求不在手机上测）。

## 1. 结论

1. **页面级转场基本到位**：底部导航切页（横移 24 dp + 淡入淡出）、进入下一级页面（从右滑入，旧页缩到 96% 并变暗）、返回、Browse 里游戏海报到详情的共享元素、弹层滑入、迷你播放器横滑关闭，这些都有，而且大多用的是 `LagoonMotion`。
2. **最显眼的缺口在播放器**：打开播放器是硬切（页面直接变黑），最大化/最小化时聊天区瞬间出现/消失，最小化后缩略图会黑一阵，返回键不能“边拖边看”，进画中画没有平滑放大。播放器是最常用的界面，这里的问题最影响观感。
3. **左右滑动切换分类整个没有**：关注页、我的页、频道页、游戏页、搜索结果里的分类，只能点上面的分段按钮，不能左右滑。v0.1 用 ViewPager，这些页面都能滑，所以这是相对 v0.1 的退步。顺带一个错误：在卡片上横滑会被当成点击（录屏里横滑频道页的直播卡片，直接打开了播放器）。
4. **同一类变化做法不一致**：关注页/我的页切分类有过渡，频道页/游戏页/搜索切分类是硬切；从“我的”切回“关注”走的是“返回”动画（整页滑出），而其他切页走的是“切页”动画；设置子页面、筛选弹层、播放器弹层子页面的进出方式各不相同；返回手势有的地方能预览（导航页、Browse 详情），有的地方不能（设置、筛选弹层、播放器）。
5. **几个“动画本身有问题”的地方**：列表逐项淡入在每次回到页面时都重放（不只是第一次加载）；“我的”页卡片淡入时露出底下红色的“删除”背景；“返回”转场少了缩放，和“前进”不对称。
6. **数值没完全收口**：播放器里还有 6 处写死的 `tween(200/250)`，聊天列表 1 处；Material 弹层的弹出/收起用的是 Material 默认动画，不是 `LagoonMotion`。

## 2. 动效规范现状（U1）

`ui/design/theme/LagoonMotion.kt`：

| 名称 | 值 | 用途（规范写的） |
| --- | --- | --- |
| `INSTANT` | 100 ms | 按压、开关、颜色 |
| `SHORT` | 200 ms | 淡入淡出、切页、小位移 |
| `MEDIUM` | 300 ms | 前进/返回、弹层 |
| `LONG` | 450 ms | 卡片展开成页面、**缩略图展开成播放器** |
| `Standard` / `Exit` | (0.2,0,0,1) / (0.3,0,1,1) | 进入和移动 / 离开 |
| `steady` 弹簧 | 阻尼 0.85，刚度 380 | 跟手拖动、弹层、**迷你播放器**、滑块 |
| `bouncy` 弹簧 | 阻尼 0.6，刚度 300 | 关注、收藏这类小庆祝 |
| `sibling` / `forward` / `back` | 见代码 | 切页 / 前进 / 返回 |
| `expand` / `collapse` | — | 开关控制的子项展开收起 |
| `reduced` | 系统“移除动画”开着 | 位移和缩放直接跳到终点，只保留淡入淡出 |

规范里写了但代码没做的：“缩略图展开成播放器”（`LONG`）、“迷你播放器用 steady 弹簧”（实际是 `tween(250)`）。

## 4. 问题排序

## 5. 分阶段方案

原则：先修错（便宜、风险低），再补播放器（最常用），再做翻页（工作量最大），最后统一和锦上添花。每个阶段一个 PR，CI 截图基线照旧（动效关闭拍图，所以大部分阶段不动基线）。

### M0 规范补充和守护检查（0.5 天，风险低）

- `LagoonMotion` 加几项，后面各阶段只用这些：
  - `back()` 进入加“从 96% 放大回来”，和 `forward()` 对称（N5）。
  - `playerSpring`（= steady，用于播放器展开/收起、迷你卡片），`playerOpen`（`LONG` + `Standard`，没有起点矩形时的兜底）。
  - `sheetForward()` / `sheetBack()`：弹层内的子页面（= `forward`/`back` 但位移 1/4 宽、不缩放，避免弹层里整页横飞）。
  - `listItem`：`animateItem` 的三种规格（淡入 `SHORT`、位移 steady、淡出 `fadeExit`）。
  - `layout`：几何变化（宽度、位置）用 steady 弹簧。
- 守护：仿 `tools/ci/legacy_ui_guard.py` 加一个检查，`ui/` 下除了 `design/theme` 以外不许出现 `tween(`、`spring(`、`keyframes(`（无限循环的加载动画列白名单）；`AnimatedVisibility`/`AnimatedContent` 不传规格的列出来人工过一遍。
- 文档：README 的“设计系统”一节补一张“哪类变化用哪个动画”的表（就是本文第 7 节）。

### M1 修错和收口（1.5 天，风险低）

1. 逐项淡入只在“这个列表第一次有数据”时放（L2）：每个分类的列表在 ViewModel/`rememberSaveable` 里记一个“已展示过”，传 `enabled = false`；返回、切回标签、滚回顶部都不再放。
2. 滑动删除的红色背景只在真的在滑时画（`dismissDirection != Settled` 或位移 > 0），淡入就不会露底（L3）。
3. 切回第一个标签用切页动画（N2）：`selectTab` 记下“这是一次切页”，`popEnterTransition`/`popExitTransition` 也查这个标记，是切页就用 `sibling`。
4. 播放器里写死的数值换成 M0 的规格（P3、P6、P11），下拉松手把手指速度传给弹簧（P3）；聊天 `animateItem` 换成 `listItem` 的数值（C1）。
5. 迷你播放器点 × 和横滑关闭一样：先滑出淡出再关（P7）；去掉 Fragment 的 `TRANSIT_FRAGMENT_FADE`。
6. 小项：快进/亮度提示淡入淡出（P12）；广告标签位移动画（P13）；提示条底边距用 steady 动画（P8）；登录底部栏走 `expand`/`collapse`（T5）。

验收：模拟器录屏逐项对照本文第 3 节；JVM 测试和截图基线不变；手机上关注页来回切 10 次，`dumpsys gfxinfo` 卡顿帧比例不高于 v0.2。

### M2 播放器转场（3–4 天，风险中）

1. **聊天跟着进度淡入淡出**（P2、P4、P17）：`ChatPlacement` 加 `alpha`（和可选的下移），由 `progress` 算：最大化时 `progress` 从 0.3 到 0 聊天从 0 淡到 1，最小化反过来；不再用“是不是完全最大化”一刀切。下面页面的露出同理跟着 `progress`，消掉中间那段黑。
2. **打开播放器有过渡**（P1）：
   - 首选“从卡片展开”：点击的卡片把缩略图在窗口里的位置传给 `startStream/startVideo/startClip`（可选参数，不改现有调用），`PlayerScreen` 以这个矩形为起点，用 `playerSpring` 展开到视频位置；页面背景、信息栏、聊天跟着进度淡入。没有起点（链接打开、通知、恢复播放）就用兜底：从迷你卡片位置展开（`progress` 从 1 动到 0，现成的机制）。
   - 视频还没出第一帧时，展开过程中缩略图位置先显示卡片的封面图，第一帧到了再淡掉封面（避免展开的是一块黑）。
3. **迷你缩略图不黑**（P5、N10）：先在手机上确认；确认有，就在 Surface 销毁前（`onStop`、最小化前）用 `PixelCopy` 截一帧放在缩略图位置，新 Surface 出第一帧（`onRenderedFirstFrame`）后淡掉。
4. **最大化播放器支持预测式返回**（P9）：`PredictiveBackHandler` 驱动 `progress` 到 0–0.25（拖动时播放器跟着缩小一点），松手提交就最小化，取消就弹回。
5. **画中画平滑进入**（P10）：`setSourceRectHint`（视频在窗口里的矩形，几何变化时更新）+ `setAspectRatio`（视频宽高比）；`setAutoEnterEnabled` 保持现状。
6. **横屏/平板布局变化有过渡**（P15、P16）：视频区和聊天的矩形用 steady 弹簧过渡。**不能每帧改 SurfaceView 的尺寸**（每次改尺寸都会重新分配缓冲，掉帧）：动画期间只改 SurfaceView 的缩放和位移（迷你播放器现在就是这么做的），动画结束再一次性设到最终尺寸。
7. 播放器菜单弹层子页面用 `sheetForward/sheetBack`，弹层里按返回先回菜单（P18，顺手统一）。

验收：模拟器录屏；**手机**上用现有的 SurfaceFlinger 图层时间戳方法（`u7/phoneframes.py`）量 gaules 1080p60 播放 5 分钟的丢帧，和 v0.2 比不能更差；最大化/最小化各 10 次的 `gfxinfo` 卡顿帧；广告替换（highlighter 切换）回归一次，确认 Surface 切换没受影响（`PlayerConnection` 的 surface 移动逻辑属于受保护的广告路径，改到就要写受保护代码声明）。

### M3 左右滑动切分类（3–4 天，风险中）

1. 关注页、我的页：把现在的 `AnimatedContent` 换成 `HorizontalPager`（`beyondViewportPageCount = 0`，只在翻页过程中组合相邻页），分段按钮的高亮块跟着翻页偏移走（现在是点了才滑）。各分类的滚动位置、顶栏折叠照旧。
2. 频道页、游戏页：现在是“头部 + 分段按钮 + 列表”在同一个网格里，翻页要改结构：头部和悬浮分段按钮放在外层，下面是 `HorizontalPager`，每页一个网格；头部折叠用嵌套滚动驱动（关注页的大标题栏已经是这么做的，可以照搬）。这是工作量最大的一块。如果审阅认为不值得，退路是：频道/游戏页只加“切分类时列表淡入 + 横向甩动切分类”的手势，不改结构（1 天）。
3. 搜索结果分组：分组是筛选芯片不是分段按钮，**不做翻页**，只给切换加 `sibling` 过渡（1/4 天）。
4. 翻页容器接管横向手势后，S7（横滑被当成点击）自然消失；另外给卡片的 `pressable` 加“移动超过触摸阈值就取消点击”，没有翻页的地方也不误触。
5. 和返回手势的冲突：屏幕左边缘的系统返回手势优先，翻页不抢（Pager 默认如此，需要验证）；频道页“聊天”分类里聊天输入框、表情面板的横向滚动不触发翻页。

验收：手机上每个页面左右来回翻 20 次，`gfxinfo` 卡顿帧比例和 v0.2 点按钮切换相比不高过 1 个百分点；毛玻璃（胶囊、分段按钮）在翻页时会重新模糊，G 阶段的经验是“内容一动就每帧重模糊”，翻页时和滚动一样，可以接受，但要量；冷启动不变（关注页首帧不能因为 Pager 多做事，用 `coldstart7.py` 对照）。

### M4 聊天与列表（1.5–2 天，风险低–中）

1. 突袭/投票/竞猜条、房间模式标签、@ 提示行用 `expand`/`collapse`（C4、C5）。
2. 表情面板 ↔ 键盘（C6）：切换时面板高度先占住键盘高度，键盘收起/弹出的过程用 `WindowInsets.imeAnimationSource/Target` 跟着走，输入框不跳。
3. 进入直播时历史消息跳动（C7）：先在手机上看是不是只在模拟器；是真问题就查历史合并时的列表 key/滚动锚点。
4. 用户操作会增删的列表加 `animateItem`（L4）：下载、收藏、筛选、最近搜索、关注列表取关后。**分页加载的长列表不加**（追加时整列位移动画没有意义，还多算）。
5. 频道/游戏页如果 M3 走了退路：切分类时新内容按 L1 的方式淡入一次。

验收：U7 的聊天压测脚本（30 条/秒，`chatstress9.sh`）手机复跑，卡顿帧不高于 v0.2；LeakCanary 跑一次。

### M5 Activity、返回手势、弹层统一（2 天，风险低）

1. 设置、登录用 `overrideActivityTransition`（Android 14+）配和 `forward`/`back` 一样的进出动画（300 ms、`Standard` 曲线、旧页 96%/40%），低于 14 的保持系统默认（N9）。要在手机上确认跨 Activity 的预测式返回还能预览。
2. 登录/退出后重启主界面用淡入淡出代替无动画（N11）。
3. 改设置回来不再整屏重建（N10）：列出哪些设置真的需要重建（主题、语言、刘海……），其余改成主界面在 `onResume` 重读；需要重建的那几项先盖一层截图再淡掉。这条工作量 1–2 天，审阅可以决定留到以后。
4. 设置宽屏右栏换页用 `sibling`（T2）；设置和筛选弹层的返回改 `PredictiveBackHandler`，跟手播放 `back`（T3）。
5. 弹层：主题里给 `MaterialTheme` 配 `motionScheme`，或者给 `ModalBottomSheet` 的状态传 `LagoonMotion` 的 steady 弹簧，让弹层和其他东西是同一种手感（D1）；内容变高用 `animateContentSize`（D2）。

### M6（可选）其余卡片 → 详情共享元素（2–3 天，风险中）

在 `MainShell` 外面包 `SharedTransitionLayout`，`composable` 的 `AnimatedContentScope` 传给页面；先做三处：游戏海报（关注页游戏、搜索结果）→ 游戏页头部，频道头像 → 频道页头像，直播卡片缩略图 → 频道页直播卡片。要确认冷启动和普通滚动不受影响（共享元素只在转场时画覆盖层）。U8 时已决定这项放到下个版本，这里只列出，放最后。

## 6. 性能怎么守

- **不加常驻动画**：所有新动画只在状态变化时跑，静止时 0 帧（G 阶段量过“空闲 0 帧”，每阶段复查 `dumpsys gfxinfo` 静止 10 秒的帧数仍是 0）。
- **视频不跟着每帧改尺寸**：一律缩放 + 位移，结束再定尺寸（M2 第 6 条）。
- **列表**：分页长列表不加 `animateItem`；逐项淡入只在第一次（M1 第 1 条，这条反而减少了工作）；翻页只组合当前页和翻动中的相邻页。
- **冷启动**：本计划不在启动路径上加任何东西；M3 和 M6 动到首屏结构，必须跑 `coldstart7.py`（v0.2 对照）。启动优化在另一个线程里做，两边的 PR 要错开合并，避免互相干扰数字。
- **量法**：模拟器只验“有没有、对不对”（录屏联系表）；“顺不顺”以手机为准：转场的卡顿帧（`gfxinfo` framestats，按操作重复 10–20 次）、播放丢帧（SurfaceFlinger 时间戳）、聊天压测。每阶段报告里放 v0.2 对照。可以给 `:benchmark` 加一个转场的 Macrobenchmark（切页、进出频道页、播放器最大化/最小化，`FrameTimingMetric`），以后每阶段自动比。
- **“移除动画”**：所有新动画都走 `LagoonMotion`，`reduced` 时位移和缩放直接到位，只留淡入淡出；每阶段在系统里关掉动画走一遍。

## 7. 统一后的规则（给后面各阶段对照）

| 变化 | 用什么 |
| --- | --- |
| 同级切换（底部标签、分段、分组、设置宽屏右栏） | `sibling`；能左右滑的地方，滑动时内容跟手，松手 steady 弹簧 |
| 进入下一级（页面、弹层里的子页面） | `forward` / `sheetForward` |
| 返回 | `back` / `sheetBack`，全部支持预测式返回 |
| 卡片 → 详情（同一张图在两页都有） | 共享元素，`LONG` + `Standard` |
| 播放器展开/收起、迷你卡片 | `playerSpring`（steady），跟手，松手带速度 |
| 临时层（弹层、提示条） | 弹层 steady 滑入 + 遮罩淡入；提示条 steady 滑入 |
| 页面内某块出现/消失 | `expand` / `collapse` |
| 列表里用户操作的增删 | `listItem` |
| 数值、颜色变化 | `fade`（颜色）、数字滚动 |
| 按压 | `pressable`（97%，bouncy 回弹） |
| 第一次加载 | 前 12 项逐项淡入，只此一次 |
