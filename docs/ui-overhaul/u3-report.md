日期：2026-11-15。分支 `ui/u3-settings-login`，PR #15。

## 1. 做了什么

### 设置

- 丢掉系统 Preference，改成一份声明式清单（`ui/settings/model/SettingsCatalog.kt`）驱动整个界面。每一项写明存储键、类型、默认值、标题、说明、图标、依赖的开关和显示条件；页面、搜索、单元测试都从这份清单来。
- 首页：账号卡片、搜索框、三组共九个分类（观看：广告屏蔽、播放、聊天、下载与录制；应用：外观、通知、备份与恢复；其他：高级、关于与更新），每行只有图标、名字和当前值（Mitchell 看过后要求去掉每行下面的说明）。
- 每个子页用分组卡片和设置行：标题、说明、当前值；单选点开是弹层选择器，数值是滑块，文本是带校验的输入弹层，危险操作先确认，全部替代系统对话框。依赖某个开关的行随开关展开收起。
- 外观页顶部有实时预览：一张示例直播卡片，随“隐藏预览图”“名字显示方式”“直播时长”“标签”“数字缩写”立即变化。
- 广告屏蔽页按定稿设计：状态卡片（当前模式、累计拦截次数和分钟、各手段的处理次数横条，全部是真实统计，没有按天的数据所以没画按天的柱状图）、三个模式卡片、五个开关、三个来源列表、高级。来源列表（自定义代理、HTTP 代理、换源）重写为 Compose 页，数据库调用沿用原 ViewModel。
- 标签页顺序（6 个）改成弹层：开关、上下移动、设为默认，存储格式和修复规则与 v0.1 相同。
- 平板和宽于 840dp 的横屏：左栏分类，右栏内容。
- 设置变化后返回主界面：需要重建的项（外观类）回传 RESULT_OK；在设置里登录或退出后回传账号已变，主界面整体重启（和其他入口的登录一样）。

### 登录

- 先是品牌页：标志、一句说明、两步说明、一个“开始登录”主按钮；第一个网页在后面照常加载。
- 顶栏显示第几步，底部是“登录时发生问题？”或电视步骤的“下一步”；三个系统对话框换成弹层；外部浏览器方式的验证码大字显示，可一键复制、打开 twitch.tv/activate。
- 登录流程、URL、客户端 ID、每个请求和令牌处理与 v0.1 逐行一致，只换界面。打开登录页即注销旧令牌的行为也保持不变。
- 两个网页是普通 View，Compose 只画顶栏、覆盖层和底栏：网页放进 Compose 的 AndroidView 后在模拟器上加载了却不绘制（第一版 qa 包在真机上也是黑屏，已修）。

### 其他

- 完整性校验窗口：全屏，顶部标题、一句说明和关闭按钮；令牌捕获代码不变。
- 应用内更新的两个对话框（主界面启动检查和设置里的手动检查）换成弹层；下载、安装代码不变。
- 恢复备份后应用总是重启（v0.1 只在恢复数据库后重启，只恢复设置文件时内存里的旧设置可能把恢复的文件写回去）。
- versionCode 5。

## 2. 删减和移动

完整对照见 `u3-settings-map.md`。删除（存储里的值都保留，没有删任何数据）：

- 主题、跟随系统、深色开启/关闭、圆角、紧凑边距、紧凑文字、Material 3：U1 起只有深色一套，没有代码读取。
- 底栏颜色：U2 的悬浮胶囊只有一种颜色。
- 顶栏随滚动抬起：U1 起已隐藏，旧页面仍以默认值读取，到 U8 删掉旧页面时一起删。
- 关注页使用标签页：U2 的关注页是一个带分段的 Compose 页。
- 广告屏蔽预设：原来是五个开关之外又存的一份副本，现在由开关推算。
- 主题页入口。

与计划不同的两处：

- 网络库选择没有删，移到“高级 › 网络”：全应用 46 处读取它，播放服务也读；满载数据快照里它的值就是 HttpEngine，删掉入口会让这样的用户再也改不回来。
- 聊天翻译没有删：计划把它放在 U7（涉及数据库目录和聊天代码），U3 只把这 3 项挪进聊天页的“翻译”分组。

聊天（47 项）和播放器按钮（33 项）按计划只换样式、分组，不删减，删减分别留给 U7、U6。

## 4. 独立审阅

另起一个代理只读审阅了整个 diff，四条红线（设置键、登录流程、受保护路径、设置变化的副作用）都干净。意见和处理：

1. 品牌页下面的网页能被点到、被读屏读到：已改，品牌页时网页设为不可见（仍在加载）。
2. 恢复时通知任务和数据库替换并行、而且重启前多等了 500 毫秒：已改，恢复顺序回到 v0.1，先等通知任务写完再继续，去掉等待；语言设置改到主线程调用（v0.1 在后台线程调用）。
3. 划掉启动时的“有可用更新”弹层会推迟下次检查：已改，只有“以后再说”推迟，和 v0.1 的“否”一样。
4. 清空文本框改为删除键而不是存空字符串：保留。读取处拿到的是默认值，等于“恢复默认”，比存空字符串让读取处自己猜更稳；令牌清空就是没有令牌。
5. 登录期间设置页被系统回收时会丢失“账号已变”：已改，存进实例状态。
6. 几个图标按钮是 40dp：已改为 44dp（触摸区 48dp）；登录页一处写死的英文读屏标签改为字符串资源。
7. 登录页和完整性校验横屏时缺少侧边避让：已改。
8. 双栏时切换分类会沿用上一页的滚动位置：已改，每页各自记位置。

## 6. 性能与体积

- qa 包 37,042,223 字节，比 G 的 36,786,437 多 0.26 MB（新增的设置和登录界面、34 个图标）；比 v0.1 的 35.95 MB 多 1.1 MB，在 4 MB 上限内。
- 冷启动：**门槛未通过**（不慢于 v0.1 的 110%）。模拟器宏基准两次都被中断（一次进程被结束，一次 GPU 模式下冷启动卡住）。之后模拟器只能从满载数据快照、软件渲染启动，于是改用 `am start -W` 测量。每个包都新装，和 v0.1 交替测试，各 8 次，下表取中位数：

  | 包 | 首帧（TotalTime） | 相对 v0.1 |
  | --- | --- | --- |
  | v0.1 | 约 500 ms（每组 488–585） | — |
  | U2 | 657 ms | 约 125% |
  | G（磨砂玻璃，合并前的 master） | 889 ms | 约 177% |
  | U3 | 878 ms | 约 175% |

  U3 与合并前的 master 持平，没有让启动变慢。比 v0.1 慢的部分，同一会话里 U2 约 +30%，G 又多出约 230 ms。U2 当时的 103.9% 是宏基准、不同的模拟器条件测的，和这次不能直接比。G 当时只在真机上比较“玻璃开、关”（同一个包），所以没看出它比 v0.1 慢。用启动参数关掉玻璃后 U3 的首帧没有变化，开销不在模糊本身；软件渲染下首次编译着色器很慢可能是原因之一，需要 trace 确认。
  Mitchell 的决定（2026-11-15）：先合并 U3，U4 之前单独查清并修复启动开销，修复效果在他的手机上和 v0.1 对比实测。第一次宏基准的原始数据（软件渲染，v0.1 不是新装，只作参考）：`E:/Projects/Lagoon-baseline/results/compare-v01-vs-u3.json`。
