## 1. 做了什么

### 浏览（游戏网格，`ui/games`）

- 海报网格：手机三列、600–840dp 四列、平板六列；海报上是观看人数，下面是主播数（沿用“显示主播数”设置）。顶栏“浏览”大标题随滚动收起，右侧搜索和账号两个按钮（账号弹层和关注页同一个）。
- 标签筛选：标签条上的“标签”打开筛选弹层，选中的标签显示为青绿胶囊，点一下去掉。长按海报：打开游戏、按这个游戏的标签筛选（v0.1 是海报上的标签文字）。
- 从网格点开游戏：游戏页在同一个 Compose 里盖在网格上，封面作为共享元素从海报飞到页头（450 毫秒、标准曲线），其余内容淡入。返回手势跟手：拖动时封面沿原路退回、页面渐隐，松手完成，取消则弹回；网格一直不透明地垫在下面，所以中途不会露出背景。播放器最大化时返回键仍归播放器（先缩小播放器，再关游戏页，实测过）。“系统移除动画”时没有共享元素，只淡入淡出。
- 再点一次底栏“浏览”：有游戏页先关掉，没有就滚到顶，和 v0.1 回到标签页首页一致。
- 带标签的“游戏”页（从游戏页的标签进入）是同一个页面，左上角是返回。

### 游戏页（`ui/game`）

- 页头：封面、名称、观看人数（红点）、主播数和关注数、游戏标签（点开是带这个标签的游戏）、关注按钮。背景是从封面取的主色做的柔和渐变，一直延伸到状态栏后面。关注状态拿到之前不显示按钮；取消关注先在弹层里确认。
- “视频、直播、剪辑”三个分段是浮动的玻璃胶囊：页头在时跟着页头走，页头滚出后钉在顶栏下面。顺序、开关和默认分段照旧读 `ui_game_tabs`。
- 每个分段一条筛选标签：直播是排序、语言、标签，视频是排序、时间范围（有 Helix 令牌才有，和 v0.1 一样）、类型、语言，剪辑是时间范围、语言。选中的标签显示成可去掉的胶囊。
- 列表：直播卡片（“紧凑直播”设为“全部”时用紧凑卡片）、视频卡片（观看进度）、剪辑卡片；长按菜单：直播是打开频道、按标签筛选、录制、分享；视频是下载、书签、分享、打开频道；剪辑是下载、分享、打开频道。
- 两个导航目的地（`gamePagerFragment`、`gameMediaFragment`）都指向这个页面；`ui_gamepager`（“游戏页使用标签页”）因此不再改变布局，键留着，播放器和频道页还在读它，U8 换纯 Compose 导航时一起删。

### 一个筛选弹层（`ui/browse/FilterSheet.kt`）

- 取代排序、语言、标签三个对话框（StreamsSortDialog、GamesSortDialog、SelectLanguagesDialog、SearchTagsDialog）。首页是排序、时间范围、类型的单选，语言和标签两行点进同一弹层里的二级页（标签页带搜索，可连选多个），返回键先回首页再关弹层。
- v0.1 的“保存排序 / 删除已保存 / 设为默认 / 保存筛选器”四个按钮改成三个开关加一个“应用”：“为这个游戏记住”（打开时就表示这个游戏已有记住的选择；关掉再应用就删除，和 v0.1 的删除按钮一样删整行）、“设为默认”、“存到我的里的筛选器”（只有直播、只有选了标签或语言时可用）。另有“重置”。
- 按标签浏览的直播页的“设为默认”照旧存在 `top_streams` 这一行。

### 按标签看直播（`ui/top`）

- v0.1 的“热门直播”页。“热门”标签页 U2 已经去掉，这一页仍是点直播标签时打开的页面：大标题是标签名，直播卡片网格，同一个筛选弹层，长按标签会加进当前筛选。

### 搜索（`ui/search`）

- 全屏搜索页：输入框自动获得焦点；空的时候显示最近搜索（胶囊，带删除和“清除”），输入时 300 毫秒后即时更新（v0.1 是 750 毫秒、只搜当前标签页）。
- 结果分组：频道、直播、游戏、视频四组，每组几条加“查看全部”；上面一排分组胶囊可以只看某一组的完整分页列表。分组的顺序和开关读 `ui_search_tabs`，标为默认的那组排第一（v0.1 先打开那个标签页）。
- 最近搜索：四个类型的记录合在一起显示（覆盖安装后 v0.1 的记录都在）；新的搜索在提交或打开结果时记下，写到每个显示中的类型下，所以存储格式不变。v0.1 每停顿一次就记一条，连输入一半的词也记。
- “通过 ID / 登录名查找用户”：搜索框右边的按钮打开弹层，“查找”先问 Twitch 这个用户在不在（不在时显示原因），“查看主页”直接打开。
- 四类都失败（比如断网）时显示错误和重试；从结果返回时保留输入和结果，不再弹出键盘。

### 删掉的旧代码

GamePagerAdapter、三个游戏列表 Fragment、四个搜索列表 Fragment、SearchPagerAdapter、StreamsAdapter、GamesAdapter、ChannelSearchAdapter、RecentSearchAdapter、StreamsSortDialog、GamesSortDialog、SearchTagsDialog（及其适配器）、11 个布局和 `search_menu`。ViewModel、数据源、数据库一行没改；排序常量从 StreamsSortDialog 挪到 `StreamSorts`。VideosSortDialog 和 SelectLanguagesDialog 频道页还在用，U5 再换。

### 其他

- `LagoonImage`：内存缓存里的图片在第一帧就显示（透明度在绘制时读），不等效果跑完。
- 外壳：`MainActivity.ComposeDestinations` 列出所有 Compose 目的地（关注加上 U4 的七个），它们铺满窗口、内容从浮动导航下面滑过；外壳记下播放器是否最大化，Compose 页据此把返回键让给播放器。
- 游戏页的四个 ViewModel 的工厂可以直接接收参数（`GameArgsKey`），这样浏览页里打开的游戏页能有自己的 ViewModel 存储，关掉就清掉。
- `BaselineComparisonBenchmark.scrollGames` 能找到新的 Compose 网格（测试标签作为资源 id）。
- 版本号 versionCode 6。

### 与计划的偏差、没做的

- 没有单独出样稿：U4 的页面全部由 U1 的组件和定稿的方案 B 拼成，和 U2、U3 一样直接实现。
- 共享元素只用在“浏览”网格到游戏页。从关注页的游戏段、搜索结果进游戏页还是普通的页面转场（它们在不同的 Fragment 里，跨 Fragment 做不了共享元素），U8 换成纯 Compose 导航后统一。
- 频道页、团队页、我的仍是旧页面（U5）。

## 2. 功能总表

U4 认领的行已在 `feature-inventory.md` 勾选：7 个导航目的地、5 个对话框类、4 个页面里的系统对话框、`search_menu`、`top_menu` 的浏览和游戏页部分。没有删除任何功能。

## 3. 自动化测试

- 本地全部 JVM 测试通过（352 项，含 7 个去广告测试文件），Lint 没有新增错误。新增 30 项：
  - `BrowseFilterTest`（13 项）：与 v0.1 的排序、筛选、保存逐条对照，分段和搜索分组的设置解析。
  - `BrowsePagingTest`（2 项）：游戏网格和直播列表加载到第 3 页无重复无缺失。
  - `BrowseInteractionTest`（15 项）：点海报、长按按标签筛选、去掉标签胶囊、游戏页分段切换和打开直播与剪辑、页头标签、关注与取消关注确认、筛选弹层改排序并记住、关掉“记住”即删除、长按直播按标签筛选、最近搜索、删除最近搜索、输入后各组搜索与“查看全部”与分组切换并记下搜索词、查找用户、返回键关闭网格上的游戏页、没有游戏页或播放器最大化时不拦返回键。
- 截图测试 `BrowseScreenshotTest`：游戏网格（加载、空、错误、有内容）、游戏页（加载、空、错误、直播、视频、剪辑）、按标签看直播、搜索（最近、结果、无结果）、筛选弹层，各拍手机竖屏、手机横屏、平板横屏和 1.3 倍字号，共 60 张。本地录过一遍逐张看过（手机横屏的页头因此把封面缩到 80dp），基线由 CI 录制。
